데이터 담당은 Supabase에 장소 데이터를 넣고, UI 담당은 GitHub의 frontend 화면을 고칩니다. 코드를 몰라도 됩니다. 이 설명서의 문장을 복사해 자신의 AI 에이전트에게 붙여 넣으면 됩니다.

1. 한눈에 보기누가 무엇을 하고, 어떻게 앱에 반영되는가
2. 팀장이 먼저 할 일초대, 키 전달
3. 공통 준비설치할 것 4가지, AI에게 말하는 요령
4. 데이터 담당 가이드장소 추가 → Supabase 업로드 → 저장
5. UI 담당 가이드화면 실행 → 수정 → 확인 → 저장
6. 함께 일하는 규칙서로의 작업이 겹치지 않게
7. 막혔을 때자주 나는 오류와 해결 문장

앱은 세 부분으로 되어 있습니다. 화면(frontend), 코스를 짜 주는 서버(backend), 장소 정보를 담은 데이터베이스(Supabase). 두 사람은 서로 다른 부분을 맡기 때문에 동시에 일해도 충돌하지 않습니다.

꼭 알아둘 낱말 6개

저장소(repository)GitHub에 있는 프로젝트 폴더. 모두가 같은 저장소를 본다.
clone저장소를 내 컴퓨터로 처음 내려받는 것. 한 번만 한다.
pull다른 사람이 바꾼 최신 내용을 내 컴퓨터로 받아오는 것. 작업 시작할 때마다 한다.
브랜치(branch)내 작업만 따로 담는 복사본. 여기서 고치면 다른 사람 작업에 영향을 주지 않는다.
commit · pushcommit은 변경을 기록하는 것, push는 그 기록을 GitHub에 올리는 것.
Pull Request(PR)"내 브랜치를 main에 합쳐 주세요"라는 요청. 팀장이 확인하고 합친다.

이 낱말들을 직접 다룰 필요는 없습니다. AI가 대신 실행합니다. 뜻만 알고 있으면 AI의 설명을 이해할 수 있습니다.

2. 팀장이 먼저 할 일 팀장

두 사람이 시작하기 전에 팀장이 아래를 끝내야 합니다.

  • GitHub 초대. 저장소 페이지 → Settings → Collaborators → Add people 에서 두 사람의 GitHub 아이디를 추가한다. 두 사람은 메일로 온 초대를 수락해야 push할 수 있다.
  • 데이터 담당에게만 Supabase 값 2개 전달. 내 컴퓨터의 backend/.env에 있는 SUPABASE_URL과 SUPABASE_SERVICE_KEY. 이 키는 데이터베이스를 전부 읽고 쓸 수 있는 키이므로 단체 채팅방이나 GitHub에 올리지 말고 1:1로 전달한다.
  • (선택) Supabase 프로젝트에 데이터 담당 초대. Supabase 대시보드 → Team → Invite. 초대하면 데이터 담당이 Table Editor에서 올린 결과를 눈으로 확인할 수 있다.
  • (선택) UI 담당에게 카카오 지도 키 전달. frontend/.env.local의 NEXT_PUBLIC_KAKAO_MAP_KEY. 없어도 대체 지도(그림 지도)로 화면이 나오므로 작업은 가능하다.
  • 아래 주소를 적어서 공유.
배포된 앱 주소 (Vercel)
Supabase 프로젝트 이름
팀 연락 채널
PR이 오면GitHub 저장소의 Pull requests 탭에서 변경 파일 목록을 확인합니다. 데이터 담당 PR에는 data/와 backend/app/data/만, UI 담당 PR에는 frontend/만 있어야 합니다. 맞으면 Merge pull request를 누릅니다.

3-2. AI에게 말하는 요령 5가지

  1. 무엇을, 어디서, 어디까지. "예쁘게 해줘"보다 "첫 화면의 시작 버튼을 더 크게, frontend 폴더 안에서만 고쳐줘"처럼 대상과 범위를 말합니다.
  2. 먼저 계획을 듣는다. "고치기 전에 어떤 파일을 어떻게 바꿀지 먼저 말해줘"를 붙이면 엉뚱한 곳을 고치는 일이 줄어듭니다.
  3. 한 번에 한 가지. 여러 요청을 한 문장에 넣지 말고, 하나가 끝나면 확인하고 다음을 시킵니다.
  4. 오류는 그대로 붙여 넣는다. 빨간 글씨가 나오면 요약하지 말고 전체를 복사해 "이 오류가 났어. 원인을 설명하고 고쳐줘"라고 합니다.
  5. 모르면 물어본다. "방금 한 일을 초보자가 알 수 있게 세 줄로 설명해줘"라고 하면 됩니다. AI가 허락을 구하면(예: 명령 실행 허용) 내용을 읽고 허용합니다.
비밀 키는 채팅창에 붙여 넣지 않습니다Supabase 키 같은 값은 AI와의 대화창이 아니라 .env 파일에 직접 붙여 넣습니다(방법은 4-1). .env 파일은 GitHub에 올라가지 않도록 이미 설정되어 있습니다.

4. 데이터 담당 가이드 데이터 담당

4-1. 처음 한 번: 내려받고 Supabase 연결하기

데이터-1 · 설치복사해서 붙여넣기
https://github.com/seungje-kwak/ai-bootcamp 저장소를 내 바탕화면에 clone 해줘. 그 다음 hackathon/README.md 를 읽고, 1) hackathon/backend 폴더에 파이썬 가상환경(.venv)을 만들고 requirements.txt 를 설치해줘. 2) backend/.env.example 을 복사해서 backend/.env 파일을 만들어줘. 값은 비워둬. 3) backend/.env 파일을 메모장으로 열어줘. 나는 초보자니까 각 단계가 무슨 일인지 한 줄씩 설명해줘.

메모장이 열리면 팀장에게 받은 값 2개를 직접 붙여 넣고 저장합니다. 등호(=) 뒤에 띄어쓰기 없이 붙입니다.

SUPABASE_URL=팀장에게 받은 주소
SUPABASE_SERVICE_KEY=팀장에게 받은 키
데이터-2 · 연결 확인복사해서 붙여넣기
backend/.env 에 Supabase 값을 넣었어. .env 의 내용은 화면에 출력하지 마. Supabase 에 연결해서 places 테이블의 행 수와 가장 큰 id 만 알려줘. 데이터는 아무것도 바꾸지 마.

행 수와 id 숫자가 나오면 연결된 것입니다.

4-2. 매번 하는 순서

① 시작 — 최신 내용을 받고 내 브랜치를 만듭니다.

데이터-3 · 작업 시작복사해서 붙여넣기
hackathon 작업을 시작할게. main 브랜치의 최신 내용을 pull 받고, data/내이름-오늘날짜 이름의 새 브랜치를 만들어서 그 브랜치로 이동해줘.

② 장소 추가 — 조사와 입력을 시킵니다. 올리기 전에 반드시 표로 확인합니다.

데이터-4 · 장소 추가복사해서 붙여넣기
먼저 hackathon/data/seed/README.md 와 backend/scripts/build_places.py 를 읽고 데이터 규칙을 파악해줘. 그 다음 아래 장소를 data/seed 의 places.csv 와 place_accessibility.csv 에 추가해줘. 식당·카페라면 food_options.csv 에도 추가해줘. 추가할 장소: 예) 제주시 탑동 근처의 1인 식사 가능한 식당 3곳 규칙: - id 는 지금 가장 큰 번호의 다음 번호부터 써줘. - 좌표(lat, lng)가 지도 범위(build_places.py 의 BOUNDS) 안에 있는 곳만 넣어줘. - 공식 사이트나 VisitJeju, 한국관광공사에서 확인한 값만 넣고, 확인하지 못한 값은 지어내지 말고 빈칸으로 둬. - 출처 주소(URL)를 place_sources.csv 에 적어줘. - last_verified_at 은 오늘 날짜로 넣어줘. - 기존 행은 바꾸지 말고, build_seed.py 는 실행하지 마. 다 되면 추가한 내용을 표로 보여줘. 내가 "좋아"라고 하기 전에는 Supabase 에 올리지 마.

이미 있는 장소의 정보를 고칠 때는 이렇게 합니다.

데이터-5 · 기존 값 수정복사해서 붙여넣기
data/seed/places.csv 에서 김만덕객주 의 운영시간(opening_hours) 을 09:00-18:00 으로 바꿔줘. 출처는 확인한 웹페이지 주소 야. place_sources.csv 에도 적어줘. 바꾸기 전과 후를 나란히 보여줘.

③ Supabase에 올리기 — 표를 확인하고 "좋아"라고 한 뒤 시킵니다.

데이터-6 · 업로드복사해서 붙여넣기
방금 수정한 데이터를 Supabase 에 반영해줘. 순서는 이렇게 해줘. 1) backend/scripts/build_places.py 실행. 건너뛴(skipped) 장소가 있으면 어느 장소가 왜 빠졌는지 알려줘. 2) backend/scripts/seed_supabase.py 실행. 3) Supabase 에서 방금 추가·수정한 id 를 다시 조회해서 값이 맞게 들어갔는지 확인해줘. 오류가 나면 멈추고 원인을 설명해줘. .env 의 내용은 출력하지 마.

④ 저장하고 PR 올리기 — CSV 파일도 GitHub에 남겨야 다른 사람의 컴퓨터와 내용이 같아집니다.

데이터-7 · 저장복사해서 붙여넣기
변경된 파일 목록을 보여주고, hackathon/data/ 와 hackathon/backend/app/data/ 안의 파일만 커밋해줘. .env 파일이 포함되지 않았는지 꼭 확인해줘. 커밋 메시지는 무엇을 추가했는지 한 줄로 써줘. 내 브랜치를 GitHub 에 push 하고, main 으로 가는 Pull Request 를 만들어줘. 직접 만들 수 없으면 PR 을 만드는 링크를 알려줘.

PR 링크를 팀장에게 보내면 끝입니다.

4-3. 데이터 파일과 규칙

파일 (data/seed/)내용주의
places.csv장소 기본 정보: 이름(한·영), 분류, 설명(영어), 좌표, 주소, 사진, 운영시간, 휴무일, 가격대한 장소 = 한 줄. id는 겹치면 안 됨
place_accessibility.csv걷기 난이도(1~3), 지형, 계단, 휠체어, 실내 여부, 앉을 곳, 화장실, 피로도(1~5)모든 장소에 한 줄 필수. 없으면 그 장소는 앱에서 빠짐
food_options.csv혼밥 가능, 비건, 채식, 할랄, 영어 메뉴, 대표 메뉴식당·카페만
phrase_cards.csv상황별 영어·한국어 회화 카드place_id 빈칸 = 공통 카드
place_sources.csv장소별 출처 주소와 메모Supabase에는 안 올라감. 기록용
항목넣을 수 있는 값
categorynature park oreum_hike beach history_culture museum market_shopping restaurant cafe 중 하나
price_levelfree low mid high
예/아니오 항목true / false / 확인 못 했으면 빈칸
좌표 범위위도 33.46~33.53, 경도 126.44~126.56 (제주시 중심부). 범위 밖은 자동으로 빠짐
last_verified_at확인한 날짜. 2026-11-12 형식
Supabase는 모두가 함께 쓰는 실제 데이터베이스입니다 업로드하면 PR과 상관없이 약 1분 뒤 실제 앱에 바로 보입니다. 그래서 ②에서 표를 확인한 뒤에 올립니다.
업로드는 "추가·덮어쓰기"만 합니다. CSV에서 줄을 지워도 Supabase에서는 지워지지 않습니다. 장소를 없애야 하면 직접 지우지 말고 팀장에게 말합니다.
Supabase 화면(Table Editor)에서 값을 직접 고치지 않습니다. CSV와 내용이 달라져 다음 업로드 때 되돌아갑니다. 화면은 확인용으로만 씁니다.

5. UI 담당 가이드 UI 담당

5-1. 처음 한 번: 내려받고 내 컴퓨터에서 띄우기

UI 담당은 Supabase 키가 필요 없습니다. 키가 없으면 서버가 저장소에 들어 있는 장소 데이터 파일로 동작하므로 화면 작업에는 충분합니다.

UI-1 · 설치복사해서 붙여넣기
https://github.com/seungje-kwak/ai-bootcamp 저장소를 내 바탕화면에 clone 해줘. 그 다음 hackathon/README.md 의 "Run locally" 를 읽고 그대로 준비해줘. 1) backend: 가상환경(.venv) 만들기, requirements.txt 설치, scripts/build_places.py 와 scripts/reset_emma.py 실행. backend/.env 는 만들지 않아도 돼(키 없이 로컬 모드로 쓸 거야). 2) frontend: npm install, 그리고 frontend/.env.example 을 복사해서 frontend/.env.local 만들기. 나는 초보자니까 각 단계가 무슨 일인지 한 줄씩 설명해줘.
UI-2 · 실행복사해서 붙여넣기
hackathon 의 백엔드(포트 8000)와 프론트엔드(포트 3000)를 둘 다 실행해줘. 켜지면 브라우저에서 열 주소를 알려줘.

브라우저에서 http://localhost:3000 을 열면 앱이 보입니다. 완성된 코스 화면을 바로 보려면 http://localhost:3000/course/e33a0000-0000-4000-8000-000000000001 (Emma 데모)을 엽니다. 코드를 고치면 화면이 자동으로 바뀝니다.

팀장에게 카카오 지도 키를 받았다면 frontend/.env.local 을 메모장으로 열어 NEXT_PUBLIC_KAKAO_MAP_KEY= 뒤에 붙여 넣고 다시 실행합니다. 없으면 그림 지도로 나옵니다.

5-2. 매번 하는 순서

① 시작

UI-3 · 작업 시작복사해서 붙여넣기
hackathon 작업을 시작할게. main 브랜치의 최신 내용을 pull 받고, ui/내이름-오늘날짜 이름의 새 브랜치를 만들어서 그 브랜치로 이동해줘. 그 다음 백엔드와 프론트엔드를 실행해줘.

② 수정 — 아래 틀에 화면, 대상, 원하는 모습을 채워 넣습니다.

UI-4 · 화면 수정복사해서 붙여넣기
어느 화면 에서 무엇을 어떻게 바꿔줘. 규칙: - hackathon/frontend 폴더 안의 파일만 고쳐줘. backend 와 data 는 건드리지 마. - frontend/lib/types.ts 와 lib/api.ts 는 서버와 약속한 형식이니 바꾸지 마. 바꿔야 한다면 먼저 나에게 말해줘. - 휴대폰 화면(폭 390px) 기준으로 보기 좋게 해줘. - 고치기 전에 어떤 파일을 어떻게 바꿀지 먼저 말해줘. - 고친 뒤에는 브라우저에서 직접 열어 확인하고 결과를 알려줘.

채워 넣은 예시입니다.

첫 화면(랜딩)에서 시작 버튼을 더 크고 눈에 띄는 색으로 바꿔줘.
코스 결과 화면의 장소 카드에서 사진을 더 크게 하고, 장소 이름 아래에 한국어 이름도 작게 보여줘.
취향 입력 화면의 선택 버튼들이 한 줄에 두 개씩 보이도록 배치를 바꿔줘.
앱 전체의 기본 색을 청록색에서 제주 감귤 느낌의 주황색 계열로 바꿔줘. 글자가 잘 읽히는지도 확인해줘.

결과가 마음에 들지 않으면 "방금 수정을 되돌려줘"라고 하거나, 화면을 캡처해 붙여 넣고 "이 부분이 이렇게 보여. 이렇게 바꿔줘"라고 말하면 됩니다.

③ 확인

UI-5 · 오류 확인복사해서 붙여넣기
frontend 폴더에서 npm run lint 와 npm run build 를 실행해서 오류가 없는지 확인해줘. 오류가 있으면 원인을 설명하고 고쳐줘. 그리고 첫 화면부터 코스 결과 화면까지 눌러 보면서 깨진 곳이 없는지 확인해줘.

④ 저장하고 PR 올리기

UI-6 · 저장복사해서 붙여넣기
변경된 파일 목록을 보여주고, hackathon/frontend/ 안의 파일만 커밋해줘. .env.local 파일이 포함되지 않았는지 꼭 확인해줘. 커밋 메시지는 무엇을 바꿨는지 한 줄로 써줘. 내 브랜치를 GitHub 에 push 하고, main 으로 가는 Pull Request 를 만들어줘. 직접 만들 수 없으면 PR 을 만드는 링크를 알려줘.

PR 링크를 팀장에게 보냅니다. 팀장이 합치면 1~2분 뒤 배포된 앱 주소에서 바뀐 화면을 볼 수 있습니다.

5-3. 어느 화면이 어느 파일인가

화면주소파일 (frontend/)
첫 화면(랜딩)/app/page.tsx
취향 입력/onboardingapp/onboarding/page.tsx
코스 결과/course/…app/course/[id]/page.tsx
구매(모의)/course/…/purchaseapp/course/[id]/purchase/page.tsx
여행 진행/course/…/tripapp/course/[id]/trip/page.tsx
장소 카드, 기사 카드, 음식 배지, 지도 등 부품—components/
전체 색·글꼴—app/globals.css, tailwind.config.ts

파일 이름을 외울 필요는 없습니다. "코스 결과 화면"처럼 화면 이름으로 말하면 AI가 파일을 찾습니다.

화면에 새 정보가 필요할 때"장소 카드에 전화번호를 보여주고 싶다"처럼 지금 서버가 주지 않는 정보가 필요하면 frontend만으로는 안 됩니다. 팀장에게 먼저 말합니다.

6. 함께 일하는 규칙

데이터 담당UI 담당
고쳐도 되는 곳hackathon/data/
hackathon/backend/app/data/ (스크립트가 자동 생성)		hackathon/frontend/
브랜치 이름data/이름-날짜ui/이름-날짜
건드리지 않는 곳frontend, backend의 코드backend, data
  1. 시작할 때마다 pull. 작업 시작 프롬프트(데이터-3, UI-3)를 매번 씁니다. 오래된 내용 위에서 일하면 합칠 때 충돌합니다.
  2. main에 직접 올리지 않는다. 항상 내 브랜치 → PR → 팀장이 합치기. 실수해도 main은 안전합니다.
  3. 작게, 자주. 하루치를 모아서 한 번에 올리지 말고, 의미 있는 단위(장소 3곳 추가, 버튼 디자인 변경)마다 PR을 올립니다.
  4. PR이 합쳐지면 새 브랜치로. 다음 작업은 다시 "작업 시작" 프롬프트부터 합니다.
  5. 맡은 폴더 밖을 고쳐야 하면 먼저 말한다. AI가 다른 폴더를 고치려 하면 멈추게 하고 팀 채널에 알립니다.

7. 막혔을 때

대부분은 오류 글자를 그대로 붙여 넣고 아래 문장을 쓰면 해결됩니다.

공통-1 · 오류 해결복사해서 붙여넣기
아래 오류가 났어. 원인을 초보자가 알 수 있게 설명하고 고쳐줘. 파일을 지우거나 되돌리는 일이 필요하면 하기 전에 먼저 나에게 물어봐. 오류 내용 전체 붙여넣기
증상원인해결
push 할 때 403 또는 permission denied저장소 초대를 수락하지 않았거나 다른 계정으로 로그인됨메일의 GitHub 초대 수락. 그래도 안 되면 "GitHub 로그인 계정을 확인하고 다시 로그인하게 도와줘"
git / node / python 을 찾을 수 없다설치가 안 됐거나, 설치 후 프로그램을 다시 켜지 않음설치 후 AI 에이전트(터미널)를 껐다 켜기. 공통-0 프롬프트로 확인
port 3000(또는 8000) is already in use이전에 켠 서버가 아직 켜져 있음"3000번과 8000번 포트를 쓰는 프로세스를 끄고 다시 실행해줘"
화면은 뜨는데 코스가 안 나오고 오류 표시백엔드가 꺼져 있음UI-2 프롬프트로 백엔드와 프론트엔드를 다시 실행
SUPABASE_URL / SUPABASE_SERVICE_KEY are not setbackend/.env 에 값이 없거나 파일 위치가 다름4-1을 다시 확인. 파일 이름이 .env.txt 로 저장되지 않았는지 확인
추가한 장소가 앱에 안 보임좌표가 지도 범위 밖이거나, 접근성 줄이 없어서 빠짐데이터-6의 1)번 결과에서 skipped 목록 확인
conflict(충돌)라는 말이 나옴같은 파일을 다른 사람도 고쳤음아래 프롬프트 사용. 판단이 어려우면 팀장에게 연락
공통-2 · 충돌 해결복사해서 붙여넣기
main 의 최신 내용을 내 브랜치에 합쳐줘. 충돌이 나면 어느 파일의 어느 부분이 충돌했는지, 내 변경과 상대 변경이 각각 무엇인지 설명해줘. 내가 고르기 전에는 한쪽을 버리지 마.
공통-3 · 지금 상태 확인복사해서 붙여넣기
지금 내가 어느 브랜치에 있는지, 아직 저장(커밋)하지 않은 변경이 무엇인지, GitHub 에 올리지 않은 커밋이 있는지 초보자가 알 수 있게 정리해줘. 아무것도 바꾸지는 마.
